# Frontend Unit-Test Traceability Matrix

## Scope and test approach

The automated frontend tests use only the repository's existing Vitest, React Testing Library, and MSW stack. MSW intercepts all API boundaries; no test calls a service outside the JSDOM test process.

- **New suite:** `src/test/ScreenCoverage.test.tsx`
- **Existing complementary suites:** `App.test.tsx`, `Workflow.test.tsx`, `OptimisticUpdate.test.tsx`, and `client.test.ts`
- **Run:** `npm test`

## Deliberate source-spec gaps / TODOs

1. **PF-key behaviours and terminal cursor placement:** `screen-flow.md` specifies PF3/PF4/PF5/PF7/PF8/PF12 and field-focus behaviour for several BMS screens. The React UI exposes routes, buttons, and pagination instead; it has no PF-key event layer or programmatic error focus. These terminal-specific behaviours are documented rather than product-changed or fabricated in tests.
2. **Rules owned by the API/batch service:** duplicate transaction ID allocation (RULE-VAL-036), record locking/rollback, card/account lookup integrity, and report batch formatting (STORY-018) are backend/batch responsibilities. Frontend unit tests assert the request/response boundary and visible failures, not persistence mechanics.
3. **Validation branches not individually exercised:** the account form's required, Y/N, name, and calendar-date branches, and the add-transaction form's required/account-card/numeric-code/merchant-ID/calendar-date branches are implemented but have not each received a dedicated test. The matrix identifies the focused branches that are asserted; no coverage is inferred from component presence.
4. **Rules not represented by current UI fields:** account-maintenance state/ZIP pairing, phone-area-code domain, SSN forbidden prefixes, and some fixed-length legacy format details have no separate modern component validation branch. No production behaviour was added solely for test coverage.
5. **Responsive implementation:** `styles.css` provides CSS media-query layout only; components contain no JavaScript viewport-dependent branch. Unit tests therefore cover semantic controls and keyboard interaction, while visual breakpoint layout remains appropriate for browser visual testing.
